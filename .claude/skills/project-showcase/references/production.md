# v2 제작 결정

## 강사의 사전 준비

전용 환경 설치와 preflight, 프로젝트 실행법, 안전한 데모 데이터를 수업 전에 확인한다. preflight PASS는 환경 확인이다. 실제 프로젝트의 내용과 화면, 최종 음성은 별도로 검토한다.

## 내용과 화면

8장은 대상 업무/기존 병목/개선 흐름/실제 입력/실제 출력/검증 결과/한계/다음 단계를 기본으로 한다. 프로젝트에 맞게 결론 제목을 바꾼다. 첫 15초 안에 대상과 문제를 전달하고, 데모는 약 40%를 목표로 하되 근거를 만들거나 같은 결과를 다른 입력에 붙이지 않는다.

화면 상태마다 source와 label을 기록한다. 배송·환불·예외 결과를 설명하면 세 결과가 각각 필요하다. 실제로 실행하지 못하면 코드 검토/미확인으로 설명 범위를 낮춘다. demo 장면에 unavailable_reason을 적고 verification은 code-reviewed/unverified로 둔다. media/states/beats 없이 실행 화면 미확보를 명시하며 임의 화면을 만들지 않는다.

## 레이아웃과 모션

problem/closing은 핵심 문구, compare는 전후 패널, flow는 단계 배열, demo는 실제 화면과 설명, evidence는 근거 표를 쓴다. 모든 장면을 같은 카드로 반복하지 않는다. 한글·자막·핵심 UI가 함께 읽혀야 한다. 실제 화면을 너무 작게 넣지 말고 필요한 영역을 캡처하거나 focus beat로 집중시킨다.

스토리보드와 대본 초안 → 정지 화면 → 대본 확정 → 음성 실측 → beats 순서로 만든다. utterance에 맞춰 replace/focus/highlight를 배치하고, 움직임 없이 읽어야 할 구간은 유지한다. 중요하지 않은 장식으로 장면을 채우지 않는다.

특별한 모션은 출력 HTML에서 조정할 수 있지만 수동 수정 보호가 적용된다. 재생성을 선택하면 --regenerate로 백업한다. 기존 수정 위에 대본 변경을 반영하려면 백업과 수정 범위를 먼저 확인한다.

## 시간 운영

제작·자동 검수 17분, 렌더 5분, 전체 청취 3분, 복구 5분은 초기 목표 예산이다. 실제 수업 증거가 아니다. estimate는 원고 분량을 미리 살피는 수단이며 합성 후 실측이 기준이다.

학생 확인·대본 수정·오류 해결까지 실제 시계로 측정한다. 시간이 부족하면 장식, 전환 복잡도, 부가 장면 순으로 줄인다. 사실 확인·핵심 데모·자막·전체 청취는 생략하지 않는다. 복구되지 않으면 오류와 남은 작업을 강사에게 전달한다.
