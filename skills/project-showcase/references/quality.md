# v2 게이트와 검수

## 세 가지 합격을 구분

1. **환경:** doctor는 버전, preflight는 실제 합성·시험 렌더까지 확인한다. 환경 PASS다.
2. **자동 검사와 프레임:** 실제 프로젝트 입력·생성물·자막·브라우저 검사를 통과하고 사람이 또는 이미지 도구를 쓴 에이전트가 실제 프레임을 확인한다.
3. **최종 청취:** 생성된 실제 MP4를 정상 속도로 끝까지 듣고 확인한다. 프레임 이미지와 음량 측정은 이를 대신하지 않는다.

검사 미실행, 브라우저 생략, 샘플 0개를 통과로 취급하지 않는다. 내용의 사실성은 source를 읽거나 실행 결과와 대조해야 한다.

## 프레임과 의미 검수

덱 8장, 첫 프레임, 장면·beat 시작과 동작 이후, 전환 직전/직후, 가장 긴 자막, 마지막 프레임을 본다. 원본 크기와 축소 화면을 함께 확인한다.

- 말하는 입력과 보이는 결과가 같은 사례인가?
- 근거 있는 내용만 실행 확인으로 표시했는가? 실행 불가 장면은 실행 화면 미확보와 구체적 사유를 표시했는가?
- focus/highlight 영역이 실제 설명 대상인가?
- 자막이 중요한 UI를 가리지 않고 읽을 시간이 있는가?
- 장면·자막·음성의 끝이 서로 잘리지 않는가?

발견은 `시간 / 장면·발화 / 문제 / 수정 / 유지할 요소`로 기록한다. 사실 오류·잘림·읽기 불가·설명과 화면 불일치는 필수 수정이다. 의도된 경고는 이유를 기록한다. 장식 개선은 시간이 남을 때 한다.

## 상태와 전달

실제 프레임 확인 후 frames 리뷰, 실제 사람의 전체 청취 답변 후 listening 리뷰를 기록한다. review 명령은 검토자의 진술을 기록하는 도구이며 자동 품질 판정이 아니다. 새 렌더는 다시 청취한다.

`export --draft`는 최신 소스·렌더·프레임 조건을 확인하되 미청취임을 표시한 검토용 ZIP이다. `export`는 최신 청취 연결도 요구한다. 최종 ZIP의 MANIFEST와 파일 해시를 유지한다. sample은 실제 프로젝트 완료와 구분한다.

## 실패와 재개

state.json과 오류 코드를 읽고 원인을 고친 뒤 해당 단계부터 재개한다. TTS는 제한된 재시도 후 실패 상태를 남기며 정상 발화 캐시는 보존한다. status는 상태 조회, recover는 비정상 종료 잠금의 생존 여부 확인이다. 실행 중 또는 다른 호스트 잠금은 임의로 제거하지 않는다.

수동 생성물 변경을 발견하면 build/resume은 멈춘다. 보존할 수정은 check 경로로 검수한다. 다시 생성하려면 --regenerate의 자동 백업을 확인한다. v1 migrate 후에는 화면 연결 검토를 완료해야 production으로 진행한다.

입력 이미지를 교체한 뒤 `E_INPUTS_CHANGED`가 나오면 `resume` 또는 `build --timed`로 다시 생성하고 검수한다. 예전 화면의 렌더를 현재 입력의 결과로 전달하지 않는다.

최종 실패를 무음 영상이나 오래된 영상으로 대체해 완료로 표시하지 않는다. 강사에게 출력 폴더·실패 단계·오류·이미 성공한 단계·다음 명령을 전달한다.
