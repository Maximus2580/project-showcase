# 강사용 v2 배포 전 확인표

이 문서는 **해야 할 확인 목록**입니다. 작성 시점의 상태는 미검증이며, 빈 항목이나 자동 검사 통과를 사람의 검수 합격으로 바꾸지 않습니다. 시험한 ZIP·PC·프로젝트·렌더 파일을 특정해서 기록하세요.

## 1. 먼저 도구 환경을 확인합니다

우선 Windows 1대와 Mac 1대에서 학생용 ZIP으로 시작합니다. 가능하면 한 대는 기존 개발자의 캐시를 사용하지 않는 깨끗한 설치 환경으로 준비합니다. [.showcase-venv 설치 안내](../.claude/skills/project-showcase/references/setup.md)를 따르고 기존 프로젝트의 `.venv`를 건드리지 않습니다.

| 확인할 일 | 통과 기준 | 현재 기록 |
|---|---|---|
| ZIP 풀기와 스킬 발견 | `.claude/skills/project-showcase/SKILL.md` 존재, Claude Code에서 스킬 사용 가능 | 미검증 |
| 전용 도구 설치 | 지원 Python·Node·Chrome·FFmpeg, 고정 의존성 설치 성공 | 미검증 |
| preflight 실행 | `preflight.json`의 환경 시험 PASS와 시험 MP4 존재 | 미검증 |
| 실제 재생 | 시험 MP4에서 한글·화면·소리 재생 | 미검증 |
| 수업 네트워크 | 학생 2~3대가 비슷한 시점에 음성 생성해도 성공하거나 오류·재개 경로 확인 | 미검증 |

`doctor`는 버전·음성 목록 확인입니다. `preflight`는 실제 합성·검사·시험 렌더까지 포함하지만 **환경 합격**일 뿐입니다. 전체 발표의 디자인·내용·음성 합격으로 표시하지 마세요.

## 2. 최종 MP4와 실제 근거를 확인합니다

현재 렌더 파일을 처음부터 끝까지 정상 속도로 듣습니다. 이전 렌더나 스냅샷으로 대체하지 않습니다. 영상 파일명과 해시 또는 내보낸 MANIFEST를 기록합니다.

| 확인할 일 | 통과 기준 | 현재 기록 |
|---|---|---|
| 근거 대조 | 주요 설명이 프로젝트 코드·실행 결과·캡처와 일치 | 미검증 |
| 입력별 화면 | 배송·환불·예외 등 다른 입력을 설명할 때 각 입력의 실제 결과가 보임 | 미검증 |
| 발화와 beat | BEATS.json의 발화·state·강조 영역이 실제 영상 시점과 일치 | 미검증 |
| 한국어 청취 | 제품명·숫자 발음, 음량, 문장 사이 흐름이 이해 가능 | 미검증 |
| 자막 | 화면을 가리지 않고, 겹침·잔류·눈에 띄는 싱크 오류가 없음 | 미검증 |
| 마지막 구간 | 마지막 음절이 잘리지 않고 결론을 읽을 여유가 있음 | 미검증 |
| 슬라이드 발표 | 8장 이동·전체화면·도움말과 데모 state 선택이 실제로 동작, 발표 PC에서 읽힘 | 미검증 |

학생에게 말한 기능·성과를 근거가 뒷받침하지 못하면 문구나 표시 상태를 수정합니다. 규칙 기반 예제를 LLM 기능으로 설명하지 않습니다. 화면 연결 오류는 장식 문제로 분류하지 않습니다.

전체 청취 후 실제 청취자와 결과로 listening 리뷰를 기록합니다. 수정으로 재렌더했다면 다시 듣습니다. 청취 전 전달은 `export --draft`이며 검수 대기입니다. 정상 `export`와 MANIFEST에서도 sample과 production을 구분하세요.

## 3. 학생의 전체 작업 시간을 측정합니다

최소 2~3대에서 다음 순서로 시험합니다. 성공 사례만 반복하는 대신 서로 다른 프로젝트 유형을 포함합니다.

1. **최우선:** 준비된 Windows와 Mac에서 같은 실제 프로젝트로 처음 요청부터 최종 ZIP까지 실행합니다.
2. **다음:** 다른 실제 프로젝트로 바꿉니다. 웹앱 외에 파일·표·로그를 결과로 내는 업무 자동화 프로젝트를 포함합니다. 보여 줄 결과 화면을 어떻게 확보하는지도 확인합니다.
3. **복구:** 대본 한 발화 수정, 수동 HTML 수정, 음성 생성 오류 후 재개를 시험합니다. 정상 캐시와 원본이 보존되는지 확인합니다. 수동 HTML 재생성이 필요하면 `--regenerate` 백업을 확인합니다.

| 시간 기록 | 시작 | 종료 | 소요 |
|---|---|---|---|
| 사전 설치·preflight (30분 목표와 별도 기록) | 미기록 | 미기록 | 미측정 |
| 프로젝트 분석·스토리보드·학생 내용 확인 | 미기록 | 미기록 | 미측정 |
| 대본 수정·음성·화면·검사 | 미기록 | 미기록 | 미측정 |
| 렌더·전체 청취·수정·최종 ZIP | 미기록 | 미기록 | 미측정 |
| 제작 총시간 (학생 대기·수정 포함) | 미기록 | 미기록 | 미측정 |

준비 완료 환경의 제작 총시간이 30분 이내이고, 필수 내용·프레임·청취 검수가 끝났을 때만 **해당 PC와 해당 프로젝트의 30분 시험 통과**로 기록합니다. 전체 학생 환경의 보장으로 일반화하지 않습니다. 넘겼다면 시간을 소비한 단계와 축소할 장식·부가 장면을 적고 다시 시험합니다. 근거·음성·자막·최종 청취를 생략해 맞추지 않습니다.

## 4. 수업에서 사용할 판정과 지원 방식

- **환경 준비:** 해당 PC의 preflight와 시험 재생 완료.
- **검수 대기:** 파일은 생성됐지만 내용·프레임 또는 전체 청취가 남음.
- **제출 가능:** 최신 렌더와 근거·프레임·전체 청취가 일치하고, 제출 ZIP의 파일 연결 확인 완료.
- **실패/지원 필요:** 필수 오류가 남음. 오래된 영상이나 무음 영상으로 완료 처리하지 않음.

학생에게 받을 지원 자료는 출력 폴더 경로, state.json, doctor/preflight 결과, 실패한 명령, 오류 메시지·관련 logs, 마지막 성공 단계입니다. 비밀키나 고객 데이터는 보내지 않게 합니다. 강사는 먼저 `status`와 오류를 읽고 정상 결과를 보존한 채 실패 단계부터 재개합니다.

시험 기록에는 날짜, 배포 ZIP 이름·해시, OS·PC, 프로젝트 유형, 전체 시간, 실제 검토자, 미해결 항목을 남깁니다. 확인하지 못한 항목은 계속 미검증으로 유지합니다.
